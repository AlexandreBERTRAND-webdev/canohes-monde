# Canohès, balade libre : plan du monde ouvert sur le département (11/11/2026)

Décisions d'alex du 11/11/2026 : zéro euro, pas de Cloudflare, pas de calcul sur le VPS, périmètre limité aux Pyrénées-Orientales. Le jeu actuel reste en ligne sur https://bertrand.al/jeu-canohes/ tant que la nouvelle version n'est pas validée.

## 1. Hébergement et calcul, tout gratuit, sans serveur

| Morceau | Où | Pourquoi | Limite à surveiller |
|---|---|---|---|
| Calcul des blocs | GitHub Actions, dépôt public | Gratuit sans plafond sur un dépôt public, 20 jobs en parallèle, 6 h par job | Les sources IGN sont ouvertes, rien de secret dans le dépôt |
| Blocs (3 Go) | Dépôt de données Hugging Face, public | Fait pour des Go, lien direct, CORS ouvert, gratuit | Dépôt public, donc données IGN redistribuées sous licence ouverte (Etalab 2.0, mention obligatoire) |
| Jeu (30 ko) | GitHub Pages | Gratuit, HTTPS, déploiement par push | 1 Go par site, on n'y met que le jeu |
| Cache des téléchargements IGN | Cache GitHub Actions (10 Go par dépôt) et copie sur Hugging Face | Ne jamais redemander deux fois la même chose à l'IGN | Le cache Actions expire après 7 jours sans usage |

Plus de Railway, plus de R2, plus de Worker, plus d'API en temps réel, plus de bloc provisoire : tout est calculé d'avance.

Coût mensuel : 0 €. Comptes nécessaires : GitHub (déjà là), Hugging Face (à créer par alex, gratuit, jeton en écriture à ranger dans ~/.config/sacha/huggingface.token).

## 2. Dimensions

- Grille Lambert-93, bloc (ix, iy) de 2 000 m, coin sud-ouest (ix*2000, iy*2000).
- Département : environ 4 116 km², soit 1 030 blocs, dont une partie en mer ou en montagne sans route, qu'on saute (bloc vide si aucun tronçon routier accessible).
- Poids mesuré sur Canohès (village dense, 1,9 km) : 5,0 Mo de géométrie, 5,7 Mo de photos en dalles de 1024 px. Photos ramenées à 512 px par dalle (92 cm par pixel) : 1,5 Mo. Estimation département : 3 Go. À confirmer sur quatre blocs de campagne à l'étape 2.
- Temps : une minute par bloc de 2 km sur 2 processeurs (à mesurer à l'étape 1). 1 030 blocs sur 20 jobs : environ une nuit.

## 3. Chaîne de production

1. `construire_bloc(ix, iy)` dans un module Python, sortie dans un dossier `blocs/<ix>_<iy>/` : `geo.bin` (binaire brut, plus de base64), `meta.json`, `sol.jpg` (atlas 4x4 de dalles 512 px).
2. Workflow GitHub Actions `blocs.yml` : entrée = liste de blocs (ou « tout le département » lue depuis la limite BD TOPO), matrice de 20 jobs, chaque job prend sa part de la liste, pousse ses blocs sur Hugging Face avec `huggingface_hub` dès qu'ils sont finis. Reprise possible : un bloc déjà présent sur Hugging Face n'est pas recalculé sauf si on le demande.
3. Graphe routier et lieux habités du département calculés une fois (job à part), publiés sur Hugging Face, lus par chaque job de bloc pour les panneaux.
4. Jeu sur GitHub Pages : `index.html` + `manifest.json` (liste des blocs disponibles et leur taille) ; chargement à moins de 2 blocs, déchargement au-delà de 3, origine flottante, mémoire graphique libérée.

## 4. Ordre de travail et preuves

1. Extraire `construire_bloc` sans changer le résultat : comparaison octet à octet avec le monde.json actuel sur Canohès. Mesurer 500 m et 2 000 m. Vérifier la couverture LiDAR HD sur le département, la présence de `position_par_rapport_au_sol` et des échangeurs dans la BD TOPO autour de Toulouges. Ces mesures se font sur le VPS (atelier de développement), pas en prod.
2. Quatre blocs autour de Canohès calculés à la main, chargement par blocs dans le jeu. Preuve : passage de bloc sans couture, poids réel d'un bloc de campagne.
3. Workflow GitHub Actions + Hugging Face + GitHub Pages sur ces quatre blocs, puis sur Canohès-Toulouges-Perpignan. Preuve : rouler de Canohès à Toulouges à 50 puis 90 km/h sans décor manquant.
4. Ponts et tunnels. Preuve : captures du pont Toulouges-Canohès dessus et dessous.
5. Panneaux de direction. Preuve : trois ronds-points et une entrée d'autoroute (A9), destinations vérifiées sur une carte.
6. Clôtures en obstacles, style par région dans un fichier `styles/roussillon.json`.
7. Calcul du département entier, mesures finales : temps par bloc, mémoire téléphone à 9 blocs, images par seconde, volume total sur Hugging Face.

## 5. Risques connus

- `compas_cgal` n'a pas de roue ARM, sans importance ici : les machines GitHub Actions sont x86.
- L'API OpenStreetMap n'est pas faite pour 1 030 requêtes : un extrait Geofabrik des Pyrénées-Orientales téléchargé une fois dans le job graphe.
- Hugging Face : un dépôt public de données IGN est licite (licence ouverte), la mention des sources est affichée dans le jeu.
- GitHub Actions : 6 h par job, donc au plus 300 blocs par job à une minute chacun ; 20 jobs suffisent.

## 6. Ce qui n'a pas été vérifié

Temps réel par bloc, poids d'un bloc de campagne, couverture LiDAR HD du département, échangeurs dans la BD TOPO. Tous à l'étape 1 et 2.
